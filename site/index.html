Right-size your Cloud SQL instances automatically.

A tool for Google Cloud SQL that analyzes real utilization and recommends — or applies — the right machine type. It looks at sustained load instead of momentary spikes, respects edition downtime constraints, and runs as a one-shot CLI or a continuous daemon. 

# Install
$ go install github.com/fraser-isbester/cloudsql-autoscaler/cmd/cloudsql-autoscaler@latest

# Analyze all instances (dry-run by default)
$ cloudsql-autoscaler --project my-gcp-project

# Apply scaling recommendations
$ cloudsql-autoscaler --project my-gcp-project --dry-run=false

What is it?

cloudsql-autoscaler watches your Cloud SQL instances and figures out when they're over- or under-provisioned. It pulls three days of CPU and memory data from Cloud Monitoring, uses P95 percentiles to separate real sustained load from temporary spikes, and recommends machine-type changes within safe constraints.

Scaling on Cloud SQL isn't free — some changes require a restart. The autoscaler understands the difference between Enterprise Plus near-zero-downtime windows and Enterprise edition downtime requirements, so it can apply changes safely. Run it once from your laptop, on a schedule, or as an always-on daemon in your cluster.

Features

01Smart P95 analysis

Uses 3 days of CPU/memory metrics and P95 percentiles to identify sustained load and avoid scaling on temporary spikes.

02Downtime aware

Understands Enterprise Plus zero-downtime windows versus Enterprise edition downtime requirements before applying changes.

03CLI · Docker · Kubernetes

Run it as a one-shot CLI, a Docker container, or a Kubernetes deployment with Workload Identity.

04Scaling profiles

Choose conservative, default, or aggressive profiles to tune how eagerly it resizes.

05Prometheus & health

Built-in Prometheus metrics plus /health, /ready, and /status endpoints for daemon mode.

06Dry-run by default

Recommendations are shown as table or json; nothing changes until you pass --dry-run=false.

Deployment

Ship it however you run infrastructure. Pull the container image and run it as a daemon, or deploy the bundled Kubernetes manifests.

Docker

# Pull and run as a daemon
docker run -d \
  -e GOOGLE_APPLICATION_CREDENTIALS=/creds.json \
  -v /path/to/creds.json:/creds.json:ro \
  ghcr.io/fraser-isbester/cloudsql-autoscaler:latest \
  --daemon --project my-gcp-project

Kubernetes

# Clone and deploy
git clone https://github.com/fraser-isbester/cloudsql-autoscaler.git
cd cloudsql-autoscaler
make deploy-k8s

# Check status
make k8s-status
make k8s-logs

Requires a GKE cluster with Workload Identity enabled and a service account with Cloud SQL Admin permissions.
